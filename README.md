# AI 起名平台（Vercel + 多模型流式 + Supabase）

零依赖的 Vercel Node 项目：用户填需求 → 选择豆包 / DeepSeek / 千问 / Kimi → 服务端流式返回 3 组名字与寓意 → 结束后把「需求 / 方案 / 模型」写入 Supabase `name_history`。

对应实验文档：阶段 1（单模型）→ **阶段 2（modelConfigMap 多模型）** → 阶段 3（建表）→ 阶段 4（GitHub + Vercel）。

## 文件结构

```
.

```

## 多模型配置（modelConfigMap）

后端只维护一张配置表，新增模型只需加一项，主调用代码不变：

| key | 平台 | 默认地址 | 密钥环境变量 | 默认模型 |
| --- | --- | --- | --- | --- |
| `doubao` | 豆包 · 火山方舟 | `https://ark.cn-beijing.volces.com/api/v1` | `DOUBAO_API_KEY` | `doubao-seed-2-1-pro-260915` |
| `deepseek` | DeepSeek | `https://api.deepseek.com/v1` | `DEEPSEEK_API_KEY` | `deepseek-chat` |
| `qwen` | 通义千问 · 百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `QWEN_API_KEY` / `DASHSCOPE_API_KEY` | `qwen-plus` |
| `kimi` | Kimi · 月之暗面 | `https://api.moonshot.cn/v1` | `MOONSHOT_API_KEY` | `kimi-k3.1-pro` |

四家都提供 OpenAI 兼容网关：同样的 `Authorization: Bearer xxx`、同样的 `messages` + `stream: true`、同样的 `delta.content` 分片，所以只需一段 `requestModel()` 共用。

## 环境变量

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `SUPABASE_URL` | 是 | `https://xxxx.supabase.co`，末尾不带 `/` |
| `SUPABASE_SERVICE_ROLE_KEY` | 是 | 服务端密钥，绕过 RLS；仅在服务端使用 |
| `SUPABASE_ANON_KEY` | 否 | 无 service_role 时的降级方案（需放开 RLS） |
| `SUPABASE_TABLE` | 否 | 默认 `name_history` |
| `DOUBAO_API_KEY` / `DEEPSEEK_API_KEY` / `QWEN_API_KEY` / `MOONSHOT_API_KEY` | 按需 | 想用哪个模型就填哪个，未填的在页面标「未配置密钥」 |
| `*_MODEL`、`*_BASE_URL` | 否 | 覆盖默认模型名 / 地址 |

本地开发：`cp .env.example .env.local` 填好 → `vercel dev`。`.env*` 已被 `.gitignore` 排除。

## 建表

Supabase → SQL Editor 执行 `supabase/schema.sql`。核心字段：

```sql
create table if not exists public.name_history (
  id                bigint generated by default as identity primary key,
  user_requirement  text not null,
  name_result       text not null,
  model_name        text not null,
  names             jsonb not null default '[]'::jsonb,
  created_at        timestamp with time zone default now()
);
```

调试期可以临时 `disable row level security`；正式上线保持 RLS 开启，服务端用 service_role 写入，前端不直连数据库。

## 接口

### `GET /api/name`

返回模型列表，前端据此生成下拉框：

```json
{
  "models": [
    { "key": "doubao", "label": "豆包 · 火山方舟", "model": "doubao-seed-2-1-pro-260915", "configured": false },
    { "key": "kimi", "label": "Kimi · 月之暗面", "model": "kimi-k3.1-pro", "configured": true }
  ],
  "defaultModel": "kimi"
}
```

### `POST /api/name`

```json
{
  "model": "kimi",
  "surname": "李",
  "type": "人名",
  "gender": "男",
  "style": ["国风大气", "英文名"],
  "length": "双字",
  "extra": "希望带草木意象，避开生僻字"
}
```

响应是 `text/plain` 流：先持续输出正文，结束时追加 `\u0000` + 元信息 JSON：

```json
{
  "modelKey": "kimi",
  "modelLabel": "Kimi · 月之暗面",
  "model": "kimi-k3.1-pro",
  "requirement": "姓氏/主体：李；用途：人名；…",
  "names": [{ "name": "李承砚", "meaning": "……" }],
  "saved": true,
  "recordId": "…",
  "saveError": null,
  "streamError": null
}
```

前端按 `\u0000` 拆分：正文做流式展示，元信息渲染方案卡片并提示是否入库。

## 部署（阶段 4）

```bash
npx vercel                 # 首次关联项目
npx vercel env add SUPABASE_URL
npx vercel env add SUPABASE_SERVICE_ROLE_KEY
npx vercel env add MOONSHOT_API_KEY      # 其余模型同理
npx vercel --prod
```

根目录 `index.html` 静态托管，`api/name.js` 映射为 `/api/name`，无需构建步骤。

## 实现要点

- 模型输出被约束为「第N组：名字 / 寓意：…」，服务端正则解析成 `names`；解析失败仍写整段 `name_result`，不丢数据。
- 客户端中途断开不写库，避免残缺记录。
- Supabase 写入失败只影响「是否入库」提示，不影响页面出结果。
- 依赖为零：Supabase 走 REST（`fetch`），不需要 `@supabase/supabase-js`；`vercel dev` 自动读 `.env.local`，也不需要 `dotenv`。
